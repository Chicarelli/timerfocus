# Error Handling 
With the application logic being implemented, there are logic erros being treated and we cannot conclude that the application will not throw any technical error. 

Initially, in development, those errors didn't follow a pattern, leading to some thrown generic Errors and some return object errors. This lead to this decision of how we will deal with errors. 

## Exception Errors + Custom Errors
As an architectural decision, the application will rely on exception-based error handling using custom error classes.

Errors will not be returned as values, as this leads to repetitive and inconsistent handling across controllers and makes it easier to break established patterns as the codebase grows.

By using custom exceptions, we can clearly distinguish between business errors and technical errors, handle them centrally, and ensure that unexpected or unhandled errors are properly captured and treated in a consistent way.

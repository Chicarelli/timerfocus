# Initial Routes from Backend
This should assume the intial routes from my backend api.

## Functionalities
These routes should attend some functionality:

The Frontend application should deal with cycles, the backend will only keep the cycles definition stored and keep track of the time. 

The cycle time will be done through events into the backend api. Start event, pause event, end event and then, work event (which will add time to the cycle)

The work events should be sent every 5 seconds, with a margin of 1 seconds less and 3 seconds later. It should consider the last time event. 

Every start should start a new cycle (id). The cycle can be finished under these conditions: 
    - if a new cycle has started (user start a new one without ending the last by refreshing the page); 
    - the work time has achieved the maximum work time defined by the user
    - the time between the last event and the new if higher than the 5 + 3 (margin). 

Only work cycles will be stored. Either work or thoughwork (afterwork though, still decide what the name will be)


## Endpoints: 

### Cycles Configuration

#### GET user/{user_id}/cycle-config
If user its not found neither device_id, them it should create a default config in the database and returned and a respective user register (with type device)

#### POST user/{user_id}/cycle-config
    {
        "userId": userId ou deviceId,
        "mode": "default" |  "learning",
        "workTime": 25,
        "thoughfulWork": 3,
        "shortBreak": 5,
        "longBreak": 10,
        "shortIntervalCounts": 4
    }


### Events Cycles

#### POST  /user_id/cycle/start
    {"type": "learning" | "default"}

#### POST /user_id/cycle/cycle_id/events
    {
        "type": 'heartbeat' | 'pause' | 'unpause' | 'end'
    }
